# Kovrix — донать быстро, играй красиво

Донат в игры и витрина игровых аккаунтов. Два приложения на React Native
и два сайта, всё хранится на своём сервере (`server/`, ставится на VPS).

| | Для клиента | Для админа и заместителей |
|---|---|---|
| Приложение Android | **Kovrix** (`com.donix`) | **KovriX A** (`com.donix.admin`) |
| Сайт | `web/user/` | `web/admin/` |

## Что умеет клиент

Внизу пять вкладок: **Донат · Аккаунты · Ответы · Топ · Профиль**.

- **Регистрация**: через Telegram-бота (номер → ID и код) или прямо
  в приложении: страна с кодом номера (+992, +7, +1…), кнопка 🎲
  придумывает случайный ник. Вход — по ID, номеру или нику.
- **Донат**: большие квадратные плитки игр, валюта (сомони, рубли, тенге,
  доллары), способ оплаты (DC Bank, Эсхата, Алиф, Mastercard, Visa),
  акция сразу снижает цену.
- **Аккаунты**: купить или продать. Витрина по играм, фото листаются
  стрелками, цена и «торг / без торга». Кнопка **«Купить»** отправляет
  продавцу сообщение и открывает чат — там договариваются об оплате. Продавцу форма подсказывает,
  какие скриншоты сделать (для Black Russia — `/mm`, баланс BC, доход
  бизнеса, `/time`, гараж, донат). После продажи — «Аккаунт продан»
  с фото чека, подтверждает админ или заместитель.
- **Ответы**: чаты, заказы с ответом админа, свои аккаунты, награды.
- **Топ**: кто больше задонатил за день, неделю, месяц и всё время,
  и задания от админа с наградой.
- **Профиль**: сколько задонатил и на каком месте, Telegram, поддержка,
  сотрудничество, поделиться приложением, несколько аккаунтов на одном
  телефоне, список устройств (лишнее можно отключить), оформление.

## Что умеет команда

Админу можно всё. Заместителю — только то, что админ отметил в его
списке доступов: донаты, аккаунты и продажи, чаты поддержки, награды,
цены и товары, акции, задания, курсы и реквизиты, блокировка.
Вкладки и разделы, на которые доступа нет, заместитель не видит,
а база такие действия не пропустит.

Всё управление — в приложении **KovriX A**, вкладка «Ещё»:

- **Люди → «Новый сотрудник»**: админ сам придумывает ник и пароль,
  выбирает «Заместитель» или «Админ», отмечает доступы и нажимает
  «Создать и дать доступ». Ник и пароль передаёт сотруднику — тот входит
  в KovriX A. Ниже в списке у каждого заместителя доступы можно
  менять (кнопка «Дать все доступы» отмечает всё разом), доступ — снять,
  человека — заблокировать или удалить вместе с его заказами, сотруднику —
  сменить пароль. Обычного клиента тоже можно сделать заместителем или
  админом: найти по имени или ID. Аккаунт сотрудника работает на любом
  устройстве: KovriX A на Android, сайт команды — на iPhone, Windows, Mac.
- **Цены и товары**: цены пакетов и «Свои товары» — добавить в любую
  игру то, чего нет в списке (ваучер, пропуск, набор) с названием
  и ценой. Клиент видит товар рядом с остальными пакетами.
- **Акции, Задания, Курсы, Реквизиты** — как названо.

Владелец — аккаунт **Imron** (вход по нику вместо телефона). Его нельзя
разжаловать или заблокировать: он записан в разделе `admins` базы.
Пароль лучше сменить в профиле.

**Первым делом** впишите реквизиты: «Ещё» → «Реквизиты». Пока их нет,
клиент на шаге оплаты видит «напишите в поддержку».

## Telegram-бот

Бот `@Kovrixtj_bot` (имя записано в `src/shared/config.ts` → `BOT_NAME`).
Каждый экран бота — одно сообщение с фоном-картинкой и кнопками под ним
(главное меню, профиль, мои заказы, пригласить друга, скачать, подарить,
помощь, а сотрудникам — «Команда» со статистикой). Фоны лежат в
`bot/assets/banners/`, перерисовать их: `swift bot/tools/banners.swift`.

**Бот команды (KovriX A)** — `bot/admin.js`, работает в том же процессе,
если в `bot/.env` задан `ADMIN_TOKEN` (отдельный бот из @BotFather).
Сотрудник входит ником и паролем из KovriX A (сообщение с паролем бот
стирает), получает новые заявки карточками с кнопками «Принять» /
«Отклонить», фото чека, сообщения поддержки и статистику за день.
Решения пишутся от имени сотрудника — права те же, что в приложении.
Вошедшие хранятся в `bot/.staff.json`.


- **Регистрация.** Человек нажимает «Регистрация» и отправляет свой номер
  кнопкой Telegram. Бот создаёт аккаунт и присылает **ID** и **код**.
  В приложении и на сайте: «Вход» → ID и код. Код — это пароль, его можно
  сменить в профиле. Если номер уже зарегистрирован в приложении, бот
  напомнит ID и подключит сообщения.
  ID и код в сообщении бота копируются нажатием.
- **Новый код** — если пароль забыт: бот ставит новый и присылает его.
- **Войти на сайт**: бот присылает одноразовую ссылку (5 минут) — сайт
  открывается сразу с аккаунтом клиента.
- **Обновить**: бот присылает свежий APK. Когда в `builds/` появляется
  APK новой версии, бот сам пишет об этом всем, кто подключил Telegram,
  а в приложениях появляется полоса «Вышло обновление».
- **Скачать приложение**: Android — бот присылает файл APK из `builds/`,
  iPhone, Windows и Mac — ссылку на сайт. Сотрудникам бот отдаёт
  ещё и KovriX A.
- **Сообщения**: клиенту — что донат зачислен, аккаунт вышел на витрину,
  пришёл ответ; админу и заместителям — о новых заказах и обращениях
  (задержка до полминуты).

Запуск:

```sh
npm run bot:on    # включить: бот запускается сам при входе в macOS
npm run bot:off   # выключить
npm run bot       # или запустить в окне терминала, до Ctrl+C
```

Что бот делал — в `bot/bot.log`. Токен от @BotFather лежит в `bot/.env`
→ `TELEGRAM_TOKEN=` (именно в `.env`, не в `.env.save`). На Mac бот
работает, только пока Mac включён и не спит. Чтобы он отвечал круглые
сутки, перенесите его на VPS (Ubuntu, 512 МБ памяти, вход по SSH):

```sh
npm run bot:vps -- root@<IP>   # копирует бота, ставит службу, выключает бота на Mac
```

После новых APK, цен или правок в `bot/` — тот же `npm run bot:vps -- root@<IP>`.
Журнал на сервере: `ssh root@<IP> tail -f /opt/donix/bot/bot.log`.

Написать человеку первым по номеру телефона бот не может — так устроен
Telegram, поэтому человек сам открывает бота и отправляет номер.
Кодов и сообщений в WhatsApp нет: для них нужен платный WhatsApp
Business API с проверкой компании в Meta.

Telegram принимает от бота файлы до 50 МБ, поэтому `npm run apk:release`
собирает APK только для процессоров телефонов (около 27 МБ).

**Как устроен «Новый код».** При входе приложение кладёт в базу ключ
восстановления аккаунта (`recovery/<uid>`). Прочитать его могут только
бот — у клиентов, и админ — у сотрудников; ключ владельца не хранится.
По нему же админ меняет пароль сотруднику: «Ещё» → «Люди» →
«Сменить пароль».

## Как выпустить обновление

1. Поднимите версию в двух местах сразу: `android/app/build.gradle`
   (`versionCode`, `versionName`) и `src/shared/config.ts` (`VERSION`).
2. `npm run apk:release` — новые файлы лягут в `builds/`.
3. Больше ничего: включённый бот увидит новый APK, запишет версию в базу
   и разошлёт сообщение. Клиент нажимает «Обновить» в боте или полосу
   в приложении и ставит файл поверх старого.

## Готовые APK

В папке `builds/` два файла:

| Файл | Для кого |
|---|---|
| `Kovrix-ПОЛЬЗОВАТЕЛЬ.apk` | для клиентов: значок — логотип Kovrix, название «Kovrix» |
| `Kovrix-АДМИН.apk` | для админа и заместителей: тот же значок с красной буквой A, в шапке метка «АДМИН» или «ЗАМ» |

Собрать заново: `npm run apk:release` (только эти два файла) или
`npm run apk` (ещё и отладочные — в `builds/debug/`). Release подписан
отладочным ключом — для Google Play нужен свой ключ.

## Сервер (VPS)

С 18 октября 2026 года Firebase больше не используется: Google заблокировал
проект `donix-5bd94`. Вместо него — свой сервер `server/server.js` (только
Node, без библиотек). Он отвечает так же, как Firebase (вход и база), и
проверяет те же правила `firebase/database.rules.json`, поэтому приложения,
сайт и бот лишь сменили адрес. Он же отдаёт сайт из `web/`. База и аккаунты
лежат в `server/data/`, копия базы — раз в сутки в `server/data/backups/`
(хранятся 30 дней).

Первый запуск на VPS (Ubuntu, 1 ГБ памяти хватит; вход по SSH-ключу):

```sh
bash scripts/vps.sh root@<IP> [домен]          # выложить и запустить всё
ssh root@<IP> 'cd /opt/donix && node server/tool.js owner Imron <пароль>'
ssh root@<IP> 'cd /opt/donix && node server/tool.js bot'
npm run bot:off                                  # бот теперь работает на VPS
```

Потом впишите адрес сервера в `SERVER` в `src/shared/config.ts`
(`https://<домен>` или `http://<IP>`), обновите `SHARE_URL`, выполните
`npm run web`, `npm run apk:release` и снова `bash scripts/vps.sh …`.
Повторный `vps.sh` обновляет файлы и не трогает базу. Остальные команды —
в начале `server/tool.js`.

## Сайт

Сайт отдаёт тот же сервер: клиент — `/user/`, команда — `/admin/`. На сайте нет
автопроверки ID, нескольких аккаунтов и списка устройств — остальное
как в приложении.

## Проверка ID игрока

Для Free Fire, PUBG Mobile и FC Mobile приложение спрашивает ID
у магазинов GoPay Games и Codashop (неофициальные адреса). Оба магазина
индонезийские: ник они показывают только для аккаунтов своего региона.

| Что ответила проверка | Что видит клиент |
|---|---|
| аккаунт из региона магазина | «Аккаунт найден: ник» |
| аккаунт из другого региона (только Free Fire) | «Аккаунт с таким ID существует», без ника |
| такого ID нет | «Проверка не нашла такой ID» — можно исправить или оформить всё равно |
| сервис не ответил | «Не удалось проверить» — заказ оформляется, ID сверит оператор |

Результат проверки записан в заказе, админ его видит. На сайте
автопроверки нет — браузер не пускает такие запросы.

| Логотип, значки, аватар бота, картинки Play, обложки игр, реклама | `bash scripts/art.sh brand` (рисует всё заново; реклама — в `ads/кибер/`) |

После правки файлов — `npm run web` (сайт) и `npm run apk:release`.

## Файлы

| Папка | Что внутри |
|---|---|
| `src/user/` | приложение клиента: главная, донат, витрина, объявление, форма продажи, «аккаунт продан», ответы, топ и задания |
| `src/admin/` | приложение команды: заявки (донат, аккаунты, продажи, награды), чаты, управление |
| `src/shared/` | общее: `config.ts`, `games.ts`, `firebase.ts` (связь с облаком), `api.ts` (что куда записывается), `store.tsx` (вход, аккаунты, настройки из облака), `Shell.tsx` (шапка и вкладки), экраны входа, профиля и чата, оформление |
| `web/user/`, `web/admin/` | сайты; `web/shared/data.js` создаёт `npm run web` |
| `bot/` | Telegram-бот |
| `server/` | свой сервер: вход, база, сайт; `setup.sh` настраивает VPS, `tool.js` — служебные команды |
| `firebase/database.rules.json` | правила базы; создаёт `npm run rules` |
| `android/app/build.gradle` | `productFlavors`: варианты `user` и `admin` |

Для iPhone собирается только приложение клиента.

## Команды

```sh
npm run android         # Kovrix на эмуляторе или подключённом телефоне
npm run android:admin   # KovriX A
npm run ios             # Kovrix в симуляторе iPhone
npm run web             # обновить web/shared/data.js из src/shared
npm run rules           # собрать правила базы
npm run server          # сервер на этом компьютере (http://localhost:8080)
npm run vps -- root@<IP> [домен]   # выложить всё на VPS
npm run bot             # запустить Telegram-бота в терминале
npm run bot:on          # бот как служба: включается сам (bot:off — выключить)
npm run bot:vps -- root@<IP>   # бот на VPS — работает, даже когда Mac выключен
npm run apk:release     # собрать два APK в папку builds/
npm test                # тесты
```

Сборке APK нужно 3–4 ГБ свободного места на диске. Эмулятор Android
и симулятор iPhone лучше не запускать одновременно.
